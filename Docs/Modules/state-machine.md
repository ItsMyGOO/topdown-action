# State Machine

## 目标

当前状态机是一个轻量、自研、可复用的基础设施，目标是服务角色级行为切换，而不是一次性做成复杂框架。

## 组成

- `IState<TContext>`
  定义状态的四个生命周期入口：
  - `Enter`
  - `Exit`
  - `Update`
  - `PhysicsUpdate`
- `StateMachine<TContext>`
  保存当前状态，并负责状态切换与更新分发

## 设计要点

- 状态机依赖上下文对象，而不是依赖具体玩家节点
- 同一个状态实例被重复切换时会直接忽略，避免无意义的重复 `Exit/Enter`
- `Update` 和 `PhysicsUpdate` 分开，便于区分普通帧逻辑与物理帧逻辑

## 为什么不引第三方库

当前阶段只需要非常有限的状态能力：

- 基础切换
- 进入/退出回调
- 帧更新

因此自研轻量实现更适合这个项目当前阶段，原因包括：

- 依赖更少
- 文档更直接
- 将来按项目需求扩展更容易
- 不会过早引入层级状态机、并行状态机等高复杂度能力

## 复用方式

状态机本身不关心是玩家还是怪物。只要未来的敌人也使用自己的 `ActorContext` 或兼容上下文，就可以直接复用同一套状态接口和切换逻辑。
