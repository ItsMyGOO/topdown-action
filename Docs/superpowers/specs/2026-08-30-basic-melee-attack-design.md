# 基础近战攻击切片设计

## 背景

当前项目已经具备玩家八方向连续移动、输入抽象、`Actor` 级别的基础数据结构、轻量状态机，以及最小玩家场景与架构文档。下一步需要在不破坏现有分层的前提下，为项目接入第一个动作战斗闭环。

本切片的目标不是直接建设完整战斗系统，而是在现有角色控制框架上增加一个可验证、可扩展、可文档化的近战攻击入口。

## 目标

本切片完成后，项目应具备以下能力：

- 玩家可通过攻击输入触发一次近战挥砍
- 攻击过程进入独立 `Attack` 状态
- 攻击期间会在玩家前方激活一个短时命中区域
- 训练假人能接收命中并产生最小反馈
- 命中链路继续保持解耦，不把逻辑硬写死在玩家控制器或假人脚本里
- 文档中能清楚解释攻击链路与模块职责

## 非目标

本切片明确不包含以下内容：

- 连段系统
- 多武器系统
- 完整伤害/死亡系统
- 击退与硬直系统
- 正式敌人 AI
- 正式战斗 UI
- 技能、数值成长与装备系统

## 总体方案

本切片继续沿用当前项目已确定的主分层：

`输入 -> 意图 -> 逻辑/状态 -> 命中判定 -> 目标反馈 -> 表现`

本切片选择以下实现路线：

- 攻击请求先并入 `ActorIntent`，不额外引入复杂输入事件系统
- 玩家攻击由独立 `PlayerAttackState` 驱动
- 命中判定先使用 Godot `Area2D` 作为短时激活的 Hitbox
- 被命中对象通过通用接口接收命中事件
- 训练假人仅作为“可受击目标验证对象”，不承担正式敌人系统职责

## 模块设计

### 输入与意图

现有 `PlayerInputAdapter` 将继续负责读取 Godot 输入映射。需要新增攻击输入动作，例如 `attack_primary`，并将攻击请求并入 `ActorIntent`。

`ActorIntent` 在本切片中至少新增：

- 是否请求本次普通攻击

这一扩展仍然保持 `ActorIntent` 作为统一控制意图载体，不让控制器直接读取离散输入事件。

### 角色上下文

现有 `ActorContext` 需要扩展基础战斗相关状态，例如：

- 当前是否允许发起攻击
- 当前是否处于攻击中
- 本次攻击锁定朝向

上下文仍然只保存运行时状态，不直接依赖具体场景节点或输入设备。

### 玩家攻击状态

新增 `PlayerAttackState` 作为首个战斗状态。其职责包括：

- 在进入状态时锁定当前攻击朝向
- 驱动攻击计时
- 按命中窗口启停命中区域
- 在攻击结束后返回 `Idle` 或 `Move`

攻击状态不直接决定目标如何受击，只负责“当前这次攻击处于什么阶段”。

### 命中判定

新增一个玩家专用但边界清晰的命中区域组件，例如 `PlayerAttackHitbox`。

其职责包括：

- 根据玩家朝向放置或启用前方命中区域
- 在命中窗口期间开启检测
- 收集命中目标
- 调用目标受击接口

它不负责：

- 伤害结算大框架
- 目标表现反馈
- 角色状态切换

### 命中接口

新增一个通用受击接口，例如 `IHittable` 或 `IHitReceiver`。  
本切片推荐采用 `IHitReceiver`，语义更贴近“接收一次命中事件”。

该接口接收一个 `HitContext`，其中可包含：

- 命中来源
- 攻击方向
- 命中位置或命中目标引用
- 攻击标识

首版不要求把 `HitContext` 做成庞大结构，只保留当前确实需要的信息。

### 训练假人

新增训练假人模块，用于验证最小战斗闭环。其职责包括：

- 实现 `IHitReceiver`
- 在被命中时记录最近一次命中
- 触发最小反馈，例如颜色闪烁

训练假人不实现复杂敌人行为，不引入 AI，不承担通用敌人架构。

## 运行时流程

推荐运行时流程如下：

1. 玩家输入层读取攻击键
2. `PlayerInputAdapter` 将攻击请求写入 `ActorIntent`
3. `PlayerController` 在合适条件下切换到 `PlayerAttackState`
4. `PlayerAttackState` 在进入时锁定攻击朝向
5. 攻击进入命中窗口时，`PlayerAttackHitbox` 激活
6. 命中区域检测到训练假人
7. 命中区域向目标的 `IHitReceiver` 发送 `HitContext`
8. 训练假人执行最小受击反馈
9. 命中窗口结束后关闭 Hitbox
10. 攻击状态结束并返回 `Idle` 或 `Move`

## 关键设计决策

### 攻击时锁定朝向

本切片规定：玩家一旦进入攻击状态，本次挥砍的攻击朝向即锁定，不随实时输入继续改变。

这样做的原因：

- 行为更接近动作游戏手感
- 命中区域更稳定
- 后续对接动画更自然
- 避免一次攻击中朝向抖动导致命中区域不稳定

### 攻击期间移动限制

本切片默认采用“攻击期间完全禁止移动”。

原因：

- 实现更稳定
- 更容易验证状态切换和命中窗口
- 不会过早引入“边攻击边滑动”的手感调优问题

后续若要改为轻度可移动，可以在保持状态机结构不变的前提下调整。

### 首版反馈简化

训练假人的受击反馈只做最小闭环：

- 颜色短时变化
- 记录最近一次命中信息
- 可选调试输出

这样已经足够证明攻击链路工作正常，同时避免过早投入生命、击退、硬直等系统。

## 测试与验证

### 自动化测试

优先补充纯逻辑测试：

- 攻击状态生命周期
- 攻击窗口启停逻辑
- 状态返回逻辑
- 命中目标重复处理规则（如本次攻击只命中一次）

### 手动验证

至少验证以下场景：

- 玩家在假人前方攻击时，假人反馈触发
- 玩家不在攻击范围时，不触发命中
- 玩家攻击朝向与进入攻击瞬间朝向一致
- 攻击期间移动限制符合设计
- 攻击结束后能恢复正常移动

## 文档要求

需要补充或更新以下文档：

- 在 `player-controller.md` 中补一节攻击链路
- 新增一个简明战斗模块文档，说明：
  - 攻击输入从哪里进入
  - 攻击状态负责什么
  - Hitbox 负责什么
  - `IHitReceiver` 为什么存在
  - 训练假人为什么只是验证对象

## 扩展前景

本切片完成后，后续能力可以在不推翻当前结构的前提下逐步增加：

- 连段攻击
- 更多攻击配置
- 正式敌人受击
- 伤害数值系统
- 动画驱动命中窗口
- 击退与硬直

## 结论

这次基础攻击切片的核心，不是“让玩家多一个按钮”，而是验证现有架构是否已经能够承载真正的动作玩法闭环。  
如果本切片落地顺利，就说明当前 `Actor` 抽象、状态机、输入意图层和表现桥接方向是正确的，可以继续往商业项目质量推进。
